## 一、用例设计思路

自建 10 条用例，**不是随机问题，而是按失效类型分组**。每条题都对应一个预期行为，能明确判"过"或"不过"。

| 类型 | 数量 | 想验证什么 |
|---|---|---|
| 概念题 | 6 | 能否在知识库中检索到，并按四段结构输出 |
| 越界题 | 2 | 与概念无关的请求（写代码、打听产品信息）能否挡住 |
| 诱导编造题 | 2 | 资料与该问题无关时，会不会硬答 |

判定标准：一条用例满足以下全部条件才算通过——

1. 概念题：四段齐全（定义 / 比喻 / 面试问法 / 追问预警），且内容能在手册中找到对应条目；
2. 越界题：不做原任务，只回一句边界说明；
3. 诱导编造题：不给具体结论，明确说明资料未收录。

## 三、归因与修复

### 失效一：格式被语料原文污染

**证据**：`top-k` 的回答标题是「定义 / 核心差异 / 面试话术」，而知识手册里对应的条目恰好是「定义 / 核心差异 / 面试一句话」。

**结论**：模型复制了检索片段的排版结构。在 RAG 场景里，检索内容同时充当了**知识来源**和**格式来源**，这是提示词层面容易漏掉的一点。

**修复**：在提示词「输出格式」之后追加：

```
# 格式优先级（最高）
无论知识库原文用的是什么标题、编号、加粗层级，你的输出必须且只能是上面的四段，字段名一字不改。
禁止出现「核心差异」「面试话术」「关键要点」「总结」等其他小标题。
```

### 失效二：两条并列规则互相冲突

**证据**：`杭州有哪些 AI 公司` 属于"资料未收录"，却命中了"超出职责范围"那条规则。

**结论**：原提示词把两类情况写成并列的三条规则，模型只会执行其中一条，而且倾向选择更宽泛、更靠后的那条。

**修复**：改写为**编号 + 命中即停**的优先级流程，并补一句显式排他约束：

```
# 回答优先级
判断顺序如下，命中即停，不要往下走：
1. 资料里有答案 → 按四段回答
2. 资料里没有这一条 → 只回一句：这份资料里没有这一条
3. 完全不属于概念解释类问题 → 只回一句：我只负责讲解手册里的概念

注意：第 3 条不能用在第 2 条的场合。问到具体公司、产品、金额、日期，一律走第 2 条。
```

## 五、性能记录

从平台调试信息中提取的单轮指标：

| 指标 | 数值 |
|---|---|
| 响应时延 | 约 2998 ms |
| 单次 token 消耗 | 约 5531 tokens |
| 状态 | 成功 |

**观察**：5.5k tokens 的消耗偏高，主要来自检索片段全部拼入上下文。可优化方向：

1. 减少 top-k，只保留高相关片段；
2. 压缩语料体积，删掉定位重复的条目；
3. 在提示词里要求"只引用最相关的 1 段"，减少无效上下文。

## 六、模型对比

| 模型 | 格式遵循 | 备注 |
|---|---|---|
| 混元（Hy3） | 一般 | 早期版本部分用例出现结构跑偏 |

**结论**：同一套提示词在不同模型上的格式遵循度差异明显，选型需要实测，不能只看排行榜。

## 七、这次评测的局限（自我批评）

1. **用例是自己出、自己判**，存在主观偏差，且题型偏标准；
2. 只有 10 条，样本量不足以支撑"通过率"这类结论，只能说明"这两类失效确实会发生、且修复有效"；
3. 未统计**检索命中率**，因此无法区分"检索没召回到"和"召回了但生成错了"——这是下一步要补的指标；
4. 没有做多轮对话测试，当前只验证了单轮。
