# AI Agent 概念教练

一个基于知识库检索（RAG）的问答智能体，把分散的 AI 概念整理成**面试时能直接复述**的四段结构，并为每一类失效设计可验证的修复方案。

> 在线体验：[yuanqi.tencent.com/webim/#/chat/fPzNWG](https://yuanqi.tencent.com/webim/#/chat/fPzNWG?appid=2115347367158017088&experience=true)（体验链接，需等待加载）

---

## 1. 要解决的问题

准备 AI 应用岗实习时遇到的真实困难：

- 概念资料分散在各处，同一个术语（如「Agent」）有多种解释口径；
- 看完能"理解"，但**说不出来**——面试被追问一句就断层；
- 面向面试的回答需要固定结构：定义、类比、可能的追问，临时组织很费劲。

所以做的不是一个"什么都能聊"的助手，而是一个**结构固定、来源可查、超范围会拒答**的概念教练。

## 2. 方案

| 环节 | 做法 |
|---|---|
| 语料 | 自建约 1.1 万字手册：33 个核心概念 + 10 组面试问答，每条含「定义／比喻／面试用法」三层 |
| 检索 | 腾讯元器知识库，默认通用分段，单库单文档 |
| 生成 | DeepSeek-V3.1-Terminus，温度低，输出结构强约束 |
| 输出 | 固定四段：一句话定义 / 打个比方 / 面试会怎么问 / 追问预警 |
| 兜底 | 资料无原文时只回「这份资料里没有这一条」，不做推测性补全 |
| 溯源 | 每条回答附参考出处，便于人工核对 |

核心设计判断：**这类工具的价值不在于答得多，而在于答得稳、查得到、该拒的时候拒得住。**

## 3. 评测结果

自建 10 条用例，覆盖三类题型：概念题（6 条）、越界题（2 条）、诱导编造题（2 条）。

| 轮次 | 范围 | 通过 |
|---|---|---|
| 第一轮 | 6 条（概念 4 + 越界 2） | **4 / 6** |
| 第二轮（修复后） | 补测 4 条 + 重测 2 条 | **6 / 6** |
| 累计 | 10 条 | **10 / 10** |

> 说明：用例由作者按手册条目自行设计，题型偏标准，真实用户的提问更发散，实际通过率会低于该结果。

性能实测（单轮）：

- 响应时延：约 **3.0 s**
- 单次消耗：约 **5.5k tokens**
- 模型对比：同一套提示词在混元与 DeepSeek 上格式遵循度存在明显差异，据此固化模型与参数

## 4. 遇到的问题与修复（本仓库的重点）

### 问题一：输出格式被语料原文的标题污染

**现象**：问「什么是 top-k」，回答用了「定义 / 核心差异 / 面试话术」三个小标题，而不是约定的四段。

**定位**：不是模型不听话——知识库原文里写的就是「定义」「面试一句话」这类小标题，模型在**模仿检索片段的排版结构**。RAG 场景下，检索到的内容既是知识来源，也是格式来源。

**修复**：在提示词中新增一段「格式优先级（最高）」，明确要求忽略原文的标题、编号、加粗层级，字段名一字不改，并列出禁止出现的其他小标题。

**结果**：重测通过。

### 问题二：「越界」与「未收录」两类规则互相冲突

**现象**：问「杭州有哪些 AI 公司」，回答是「我只负责讲解手册里的概念」——把人赶走了，而正确行为应是「这份资料里没有这一条」。

**定位**：提示词里两条规则并列存在（一条管越界提问、一条管资料未覆盖），模型优先命中了更笼统的那条。**并列规则之间存在歧义时，模型会挑一条执行，而不是都执行。**

**修复**：把并列规则改写为**编号 + 命中即停**的优先级列表（1 有答案→四段回答；2 未收录→只回一句；3 完全越界→只回一句），并补一句显式约束：第 3 条不得用于第 2 条的场合。

**结果**：重测通过，两类问题不再串线。

### 一点结论

提示词"不生效"，多数时候不是模型能力问题，而是**规则本身的歧义**。与其反复加强语气、堆感叹号，不如把规则改成有顺序、可判定的流程。
